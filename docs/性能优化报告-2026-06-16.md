# 性能优化报告

日期: 2026-06-16
范围: downloadkit 项目代码审查
方法: 静态分析，无代码修改

---

## 一、严重 — 修复后有明显性能提升

### P1. ttwid 每次解析重复获取

**位置**: `downloadkit/douyin.py` L323-363, 调用点 L437, L568
**问题**: 每次调用 `parse()` 都重新 HTTP 请求 `ttwid.bytedance.com/ttwid/union/register/`（最多 3 个配置依次试）。实际上 ttwid 在服务器端是长时间有效（小时级），一次 session 只需拿一次。
**当前影响**: 每次解析额外增加 1~3 秒延迟（3 个配置串行尝试）。
**建议**: 类变量缓存 `_ttwid_cache`，首次成功后直接复用。

### P2. 三阶段签名串行尝试累计超时

**位置**: `_fetch_slides_via_api()` L481-508, `_fetch_via_aweme_detail_api()` L626-652
**问题**: 每个 API 调用都是 X-Bogus（6 配置）→ a_bogus（2 配置）→ 裸请求（6 配置）三阶段串行。每个请求 timeout=15s，最坏情况：14 × 15s = 210s（3.5分钟）。且第二阶段等第一阶段全部失败才开始。
**当前影响**: 一次完整解析可能在最坏情况下花 3~4 分钟。
**建议**: 三阶段用 `asyncio.gather` 并行发送，任一成功即 `cancel` 其他 pending 请求。或设置整体解析超时（如 60s）。

### P3. 图文解析 Playwright 浏览器循环过重

**位置**: `_parse_via_browser()` L807-988
**问题**: 5 轮 × N 张幻灯片 × 1500ms wait = 很慢。10 张幻灯片最坏 5 × 10 × 3s = 150s。
**当前影响**: 实况照片解析可能耗时 2.5 分钟。
**建议**: 
- 减少轮数到 2~3 轮（抖音加载速度一般 1~2 轮就够了）
- 缩短单次等待到 800ms（实测足够触发视频加载）
- 只循环未配对的幻灯片，已配对的跳过

## 二、中等 — 建议优化

### M1. `_load_user_cookies()` 多次文件 I/O

**位置**: L365-420, 调用点 L440, L574
**问题**: 每次解析调用两次（`_fetch_slides_via_api` + `_fetch_via_aweme_detail_api`），每次都读文件 + 尝试浏览器 cookie。
**建议**: 类变量缓存 cookie 字符串，首次加载后复用。

### M2. 第三方 API 使用 `print()` 而不是 logger

**位置**: `downloadkit/douyin_third_party.py` 几乎所有 parser
**问题**: `print(f"[Limmy] ...")` 等没有走 logging 模块，混杂在 stdout 中。
**建议**: 改用 `logger.info()`，与主代码风格统一。

### M3. 视频下载没有流式进度

**位置**: `download_content()` L1678-1814
**问题**: `download_file()` 下载大视频时没有分块进度回调，只有开始和完成。
**建议**: 增加分块下载进度回调，提升 Web UI 体验。

## 三、轻微 — 顺手可修

### T1. logger 赋值重复

**位置**: `douyin.py` L23 和 L27
```python
logger = get_logger("douyin")   # L23
logger = logging.getLogger(__name__)  # L27 — 覆盖了上面的
```
实际上 `get_logger("douyin")` = `logging.getLogger("downloadkit.douyin")` = `logging.getLogger(__name__)`，返回同一个 logger 对象，但 L27 赋值是冗余的，应删除。

### T2. `_extract_json` 尾逗号正则开销

**位置**: L1222-1223
**问题**: `re.sub(r',\s*}', '}', json_str)` 和 `re.sub(r',\s*]', ']', json_str)` 在完整 JSON 字符串上运行正则。如果匹配到的 JSON 很大（几万字符），正则性能有影响。
**建议**: 可以用 `json.loads(s, strict=False)` 或用更精确的切片限制正则范围。
