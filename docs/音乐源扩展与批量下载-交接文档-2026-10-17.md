三个模块沿用项目既有的**独立异步函数模式**（不是 `BasePlatform` 子类）：

理由：接入 `BasePlatform` 要把 musicdl 的整套客户端（签名、分页、鉴权）搬进来，400+ 行且要长期跟着对方改；独立函数模式只需"搜索命中 + 拿一个可下载 URL"，与 `itzo.py` / `gequbao.py` / `migu.py` 完全一致。

下载链现在 **8 级**（`downloadkit/downloader.py`）：

```
平台直链 → itzo → gequbao → migu → kuwo → kugou → soda → yt-dlp
```

### 1.2 歌单后台批量下载

设计取舍：小歌单用前端串行（原有行为不动），大歌单走后台队列，避免一次性创建几百个任务把 UI 卡死。

### 1.3 两个故障的修复

| 故障 | 现象 | 根因 | 修复 |
|------|------|------|------|
| 汽水在**打包版**必然失效 | 歌单里只有第一首下载成功，其余全部落到 yt-dlp 后失败 | `soda._extract_audition_url()` 里 `import json_repair`，而这个包**从未写进 pyproject 依赖**，venv 与 exe 里都不存在；`ModuleNotFoundError` 被外层 `except Exception` 静默吞掉（只写 debug 日志） | 改为标准库 `json` 优先解析，`json_repair` 降为可选兜底；失败日志从 debug 提到 **warning** |

## 二、关键坑（接手必读）

### 坑 1：开发环境有、打包 exe 里没有的依赖

`json_repair` 只装在**系统 Python**（`C:\Users\AQ\AppData\Local\Programs\Python\Python312`）里，而打包用的是项目 `.venv`。开发期用系统 python 手写探针脚本验证"汽水能下" → 结论正确但**对打包版无效**。

**纪律：**
1. 任何新 `import`，先在 venv 里确认：`.venv\Scripts\python.exe -c "import X"`
2. 每次打包后扫一眼 `build/downloadkit/warn-downloadkit.txt`，搜 `missing module named`
3. 交叉验证工具的权威判据是 `build/downloadkit/PYZ-00.toc`（在不在包里）+ `Analysis-00.toc`

本次实证：`PYZ-00.toc` 里 `json_repair` 命中 **0** 条，`httpx` **1** 条。

### 坑 2：GUI 程序的子进程会弹窗

`build/pyinstaller/downloadkit.spec` 里 `console=False`，父进程没有控制台，此时启动控制台程序（`yt-dlp.exe` / `ffmpeg.exe` / `powershell.exe`）**系统会新开一个控制台窗口**。

**约定：新增任何子进程调用点，一律带 `creationflags=CREATE_NO_WINDOW`。**

已覆盖的 5 处：

| 位置 | 子进程 |
|------|--------|
| `downloadkit/downloader.py:250` | ffmpeg（m4a→mp3 转码） |
| `downloadkit/downloader.py:293` | yt-dlp（音乐兜底） |
| `downloadkit/generic_video.py:213` | yt-dlp（视频解析） |
| `downloadkit/bilibili.py:377` | ffmpeg（音视频合并） |
| `server.py:740` | powershell（选目录对话框；只压控制台，对话框照常弹） |

**不需要改的**：`server.py` 的 `explorer` / `os.startfile`（用户主动点"打开文件夹"，本来就该弹）、`run.py` 的重启分支（已用 `DETACHED_PROCESS`）、`cli.py` 的 `os.system("")`（CLI 专用，GUI 路径不导入）。

对照实验（无控制台父进程 `pythonw.exe` 下跑，Windows 11 默认终端是 Windows Terminal）：

```
不加 creationflags   → 期间新增可见控制台窗口 = 2
    class='CASCADIA_HOSTING_WINDOW_CLASS' title='C:\Windows\SYSTEM32\ping.exe'
    class='PseudoConsoleWindow' title=''
加 CREATE_NO_WINDOW  → 期间新增可见控制台窗口 = 0
```

注意：`CASCADIA_HOSTING_WINDOW_CLASS` 说明新窗口的类名**不是**老的 `ConsoleWindowClass`，排查时不要只认 conhost。

### 坑 3：汽水（soda）接口细节

| 用途 | 接口 | 要点 |
|------|------|------|
| 搜索 | `https://api.qishui.com/luna/search/track` | 固定参数 `device_platform=android, os=android, aid=386088, app_name=luna, iid=850377327519292, device_id=3753066532709850`；曲目在 `result_groups[0].data[].entity.track` |
| 直链 | `https://music.douyin.com/qishui/share/track?track_id=...` | SSR 注入 `_ROUTER_DATA = {...};`；取 `loaderData.track_page.audioWithLyricsOption.url`。**注意这是 `video/tos/...` 的 M4A(AAC 128k)，非 MP3**，落盘前会被 ffmpeg 转码 |
| 歌单 | `https://api.qishui.com/luna/pc/playlist/detail` | 参数 `playlist_id, cursor, cnt, aid=386088, device_platform=web, channel=pc_web`；曲目结构是 **`entity.track_wrapper.track`**（≠ 搜索接口的 `entity.track`） |
| 歌单短链 | `https://qishui.douyin.com/s/<code>` | **必须跟 302** 才能拿到真实 `playlist_id`（例：`iXsDwgKv` → `7294976899776167951`）；短码直接当 ID 传会得到 `status_code=1000004 ERR_INVALID_PARAM` |

业务错误码：`1000004 = ERR_INVALID_PARAM`（ID 格式不对）、`1000005 = ERR_RESOURCE_NOT_FOUND`。**判断成败不能只看 `status_code != 0`** —— 正常响应里 `status_code` 可能是 `None`，把它当错误会直接断掉整页解析（这个坑踩过）。

`bit_rates` 是**列表**不是字典。VIP/无损路径 `luna/pc/track_v2` 需要登录 cookie + AES-GCM 解 `PlayAuth`，**本次刻意没做**。

### 坑 4：异常吞掉的代价

上一轮的 `except Exception: logger.debug(f"[soda] track page failed: {e}")` 让"每首歌都失败"这件事在 INFO 级别日志里**完全不可见**，排查绕了一大圈。

**约定：所有降级/兜底分支的异常，至少 `logger.warning` 并带上 `type(e).__name__`。**

## 四、遗留问题 / TODO

按优先级：

1. **`batch_size` 实际上没生效**（本次发现）
   UI 传的 5 只被记进任务信息，真正并发由 `downloadkit/download_queue.py:288` 写死的 `max_concurrent=3` 决定。
   要做真并发控制，需让 `DownloadQueue` 支持按批调整信号量（注意别影响其他任务）。

2. **kuwo / kugou 的直链兜底链全挂**（非本次引入）
   - kugou：`api.baka.plus` 404、`music.lzmhhh.com` 500（另有 `music-api.gdstudio.xyz` 未验证）
   - kuwo：官方 `mobi.kuwo.cn/mobi.s` 实测 404，兜底依赖 `lxmusicapi.onrender.com`（flac）/ `music.nxinxz.com`（lossless）
   - **只验证过搜索，直链兜底链没有端到端验证过**（当时探针不稳定）
   要修得重新找可用镜像，或实现官方签名。

3. **migu 源已失效**：`m.music.migu.cn/migu/remoting/scr_search_tag` 返回 HTML 不是 JSON。

4. **gequbao 间歇性 `ConnectError: All connection attempts failed`**（重试 3 次仍失败，持续约 1 分钟）。
   注意各平台模块用 `httpx(trust_env=False)`，**会忽略系统/环境变量代理**；如果本机走代理，会出现"yt-dlp 能联网而音乐源不能"的差异，排查时先分清这一层。

5. **汽水只走免费 audition_url**（128kbps AAC），VIP/无损未做。

6. **368 首大歌单未跑全量**：只验证了前几首 + 单曲下载。全量跑一次能顺带暴露限流/并发问题。

7. **打包版不自带 yt-dlp.exe / ffmpeg**：`_yt_dlp_cmd()` 先找 `sys.executable` 同级目录（`dist\`），找不到就 `shutil.which()` → 依赖用户 PATH。要彻底可移植需把两者打进包。
